# 常见问题

## 组合控件首次打开正常，切换页面或回池复用后出现背景错位、空间异常

记录日期：2026-09-18。

### 现象与验证状态

- 第一次打开设置页正常，切换到其他页面再返回后，内部卡片、控件或背景尺寸不一致。
- 可能看起来像背景叠加、亮度变化，也可能挤压下一组或使点击区域与画面不一致。
- 用户已初步验证文字组的先行修复有效。本次将相同的布局收尾原则推广到其他保留的组合控件。
- 本次公共机制的 Lua 5.1 模拟回归与语法检查通过；其余各组的游戏内显示仍待实际验证。不能把模拟测试等同于游戏内验收。

### 已确认的代码问题

1. 首次创建与回池复用走不同的背景处理路径。原通用复用辅助函数会追加通用面板；部分组首次没有这层背景，材质组首次则使用原有 Backdrop。
2. 组合组先做内部排版，Grid 随后才确定最终像素尺寸，内部控件和背景可能仍按前一个尺寸布局。
3. 同尺寸复用或更换父级缩放，不一定触发尺寸变化事件。只依赖 OnSizeChanged 更新缓存背景，无法保证最终几何已同步。
4. 此前最终尺寸后的处理和整行设置列表的处理只专门覆盖了文字组，其余组没有统一走相同流程。

这些问题不等于“每次打开都创建几十层背景”。公共圆角背景有缓存；重排次数和背景层数需要分别核对。

### 本次处理

公共入口位于 `Core/GUI/ExwindGUI.lua`：

- `EXUI:LayoutCompositeGroup(host, width, height)`：设置宿主尺寸，调用该组原有内部排版，再同步已有背景。
- `EXUI:RefreshCompositeSurfaces(host)`：更新当前组及其子控件、登记弹窗的缓存背景几何；同一对象只访问一次。
- 背景同步沿用已有颜色、透明度与启用状态，不创建另一层面板，不把已清除的背景重新启用。
- 组合设置组的首次创建和复用均进入上述布局入口。旧预览／物品壳原本明确使用的面板保留，不借本次修复更换样式。

`Core/GUI/ExwindGrid.lua` 在宿主最终像素尺寸确定后统一完成组合布局，移除卡片路径里提前进行的重复内部排版。整行借用组合控件的设置列表也使用同一入口。

在线编辑器中已有的、允许手动设置高度的空通用卡片继续保留其声明高度。

`Core/GUI/ExwindChoiceGroup.lua` 保留标签页／选项组自己的布局方式，在布局完成后同步已有背景；分段选择复用这条路径。

### 覆盖范围

| 组合类型 | 接入方式 |
| --- | --- |
| 文字、图标、计时条、锚点、排列 | 公共组合布局入口与 Grid 最终布局 |
| 材质、声音、当前公开发光组 | 公共组合布局入口与 Grid 最终布局 |
| 模块通用设置组 | 原字段布局计算完成后统一收尾 |
| Aura 原生计时条、层数条、驱散边框、排序、子元素 | 复用模块通用组，因此一并覆盖 |
| EXBoss 额外子元素设置 | 复用模块通用组；五行呈现及原字段结构未改 |
| 物品配置行、物品信息展示 | 既有组合辅助流程与 Grid 最终布局 |
| 标签页、选项组、分段选择 | 自有布局完成后同步缓存背景 |

已删除的旧语音触发组不恢复。历史发光别名不作为新的独立实现改造。

### 保持不变的范围

- 不统一所有页面的宽度，不改各组原有默认宽度、断点、颜色、字段顺序和选项。
- 不改配置表引用、字段映射、默认值、初始化、保存、通知或业务回调。
- 不创建临时配置、影子配置或数据兼容层。
- 不改变对象池的归还规则，不额外添加定时器或反复注册事件。

### 验证记录与后续验收

已使用生产公共函数在 Lua 5.1 模拟环境检查：同尺寸反复复用、父级缩放变化、外置弹窗背景更新、去重、隐藏背景不复活、颜色与透明度保留、最终像素尺寸后重排、编辑器高度保留，以及公共布局不访问配置或触发通知。

对照改前 Grid 代码，模拟测试能够检出非文字组合控件缺少最终重排的问题；修改后通过。该测试验证公共机制，不代表每个控件的内部业务与游戏显示均已测试。

游戏内建议 `/reload` 后依次验证：首次打开、同页重开、两个含相同组合类型的页面之间来回切换、打开子设置弹窗、关闭整个面板后再打开。检查背景边界、亮度、下一组间距和实际点击位置是否与首次一致。

如果仍有异常，应对照首次与复用后的最终尺寸、背景状态和所属父级定位具体差异，不直接修改业务数据或靠增加背景层遮盖问题。
